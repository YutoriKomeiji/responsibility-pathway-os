権限・証拠・外部作用・人間の責任を、途中で切らない。

RPOSは、影響を伴うソフトウェア操作のためのPythonレイヤーです。実行前の権限確認から、外部作用の不確実性、再起動、照合、修復、Human Gateへの返却まで、Responsibility Pathwayを明示的に保持します。

課題

APIが成功を返したことと、外部作用が検証されたことは同じではない。

権限は文脈依存

actor、operation、action、evidence、context、time、target、exact effectを束縛し、権限を永続的なbooleanとして扱いません。

不明は不明のまま

外部作用が起きた可能性はあるが検証できない場合、成功や自動再実行へ勝手に変換しません。

回復でも責任を保持

再起動やreconciliation後も未解決経路を保持し、repairまたはHuman Gateへ返します。

Core lifecycle

責任はフラグではなく経路。

PROPOSED→AUTHORIZED / HUMAN_GATE→DISPATCHING→VERIFIED / EFFECT_UNKNOWN→COMPLETED / REPAIR_REQUIRED / HUMAN_RETURN

Formal Assurance Surface

境界を機械検証し、同時にproof ceilingも見せる。

RPOSはLean 4を利用者から見えるassurance layerとして扱います。公開Viewerは、siteと同じexact commitでpinned lake buildが成功した後に生成され、Operational RiskからLean theorem、Python runtime evidence、source hash、model scope、proof ceilingまで辿れます。

Formal Assurance Viewerを開くverified Architecture Mapsを開くLean sourceを見る

AssuranceはAuthorityではない

  • Lean evidenceはoperationをauthorizeしない
  • formal proofはHuman Gateを承認しない
  • abstract theoremはexternal effectを検証しない
  • runtime testとoperational evidenceは別evidence layerとして残す
  • 表示する各assertionにproof ceilingを明示する

Evidence boundary & promotion

Public Alphaは永久的な免責ではなく、現在のevidence stateです。

RPOSは、evidenceが揃えば前進できる境界と、software単体では越えるべきでない恒久責任境界を分離します。Production readiness、platform support、implementation-wide formal conformance、supply-chain trust、domain effectivenessは、宣言したevidence criteriaが満たされreviewされた場合にのみ昇格します。

昇格条件を見る

恒久的な責任境界

  • softwareは法的・組織的authorityを生成しない
  • receiptだけをexternal effectの証明にしない
  • 経路を管理してもthird-party system自体の正しさは生成しない
  • 必要contractを持たない任意外部systemへuniversal exactly-onceを保証しない
  • abstract formal proofだけでruntime/deployment全体を証明済みにしない
